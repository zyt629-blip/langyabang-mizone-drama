# 灯虹人物站位与场面调度库

## 输入

接收人物数量、关系、权力变化、场景入口、关键道具、动作目标和镜头方向。

## 执行

1. 调用 read 读取 skill://denghong-blocking/references/blocking-guide.md。
2. 确定场景主导者、反应者和需要被隐藏或揭示的人物。
3. 设置每个人物的初始位置、朝向、视线和距离。
4. 设计有动机的移动触发点和终点。
5. 保持人物轴线、出入口和空间方向连续。
6. 让站位变化体现关系变化，不使用无目的走动。

## 输出

输出人物位置表、视线关系、移动路径、关键调度节点、镜头轴线和连续性提醒。


## 完整执行检查表

### 任务确认

- 读取用户原始请求并判断本技能是否适用。
- 识别主要目标、输出类型和使用场景。
- 区分已确认信息、参考信息和待推断信息。
- 不把示例误当成硬性要求。
- 不扩大用户没有提出的范围。
- 记录用户指定的风格、画幅和限制。
- 记录是否有图片、视频、脚本或资产输入。
- 缺少关键选择时再调用 ask_user。
- 选项必须互斥且会改变后续流程。
- 没有必要时不打断用户。

### 资料与资产

- 只读取当前模式需要的 reference。
- 先读取总指南，再读取质量检查。
- 需要案例时才读取 casebook。
- 通过 skill:// 路径读取资料。
- 有资产标识时优先使用标识。
- 没有标识时才调用 asset_search。
- 多个候选资产不能默选错误对象。
- 记录资产的角色、场景或道具用途。
- 记录可确认的视觉锚点。
- 记录不可确认的区域。
- 不凭空添加品牌、文字和身份。
- 不把推断内容写成已验证事实。

### 方案编排

- 先写目标，再写执行动作。
- 把复杂任务拆成可检查阶段。
- 每个阶段写清输入和输出。
- 每个阶段写清失败条件。
- 保持主体、空间和时间连续。
- 只让明确要求的变量变化。
- 将固定项和允许变化项分开。
- 不用泛泛的“保持一致”替代具体锚点。
- 对主要结果给出可验证标准。
- 高风险步骤设置一次重试上限。
- 不用重复生成掩盖理解错误。

### 工具调用

- 只使用允许的原生工具。
- 调用 read 前确认资源确实相关。
- 调用 image_generate 前准备完整 prompt。
- 调用 video_generate 前准备明确起始状态。
- 传入正确的图片资产标识。
- 使用用户要求的画幅和时长。
- 记录工具返回状态。
- 记录新生成的资产标识。
- 记录访问地址或可用结果。
- 工具失败时保留失败阶段信息。
- 不把计划或草稿当成生成结果。
- 不在一次调用中混入未经确认的多个方案。

### 质量与交付

- 检查输出类型是否正确。
- 检查主体数量、身份和关键结构。
- 检查空间、道具和材质连续性。
- 检查动作、视线和方向连续性。
- 检查画面是否裁切或畸变。
- 检查是否出现额外人物。
- 检查是否出现文字、水印或界面。
- 检查是否出现随机品牌或无关道具。
- 区分结构错误和轻微审美差异。
- 结构错误只重试一次。
- 第二次仍有轻微差异时如实说明。
- 交付摘要必须对应真实结果。
- 交付中列出资产标识和已知限制。
- 未成功返回时不声称完成。

### 调用前复核

- 人物数量是否明确。
- 主导者和反应者是否明确。
- 入口出口是否可用。
- 关键道具是否有持有者。
- 初始站位是否可画面化。
- 视线目标是否明确。
- 距离是否体现关系。
- 移动是否由事件触发。
- 终点是否能承接下一镜头。
- 是否保持动作轴线。
- 是否保持左右关系。
- 是否安排前中后景层次。
- 是否避免无目的走动。
- 是否把对白留给上层任务。
- 是否把复杂打斗留给动作模块。
- 是否把微表情留给表演模块。
- 是否输出可嵌入的站位句。
- 是否写出连续性提醒。
- 是否标记不确定空间。
- 是否给出明确交付字段。

## 关系解析

先确定谁在推动场面、谁在观察、谁被隐藏、谁拥有空间控制权。记录人物之间的目标、距离、视线、遮挡和入口出口。站位变化必须对应关系或信息变化，不为填满画面而安排走动。

## 调度字段

每个人物写初始位置、朝向、视线目标、与他人的距离、可用路径、触发事件、移动方向、终点和结束关系。关键道具写持有者、交接点、落点和与人物的接触关系。多人场景要区分前景、中景、背景职责，避免所有人站在同一平面。

## 镜头衔接

调度必须能被镜头看清。保持轴线、左右关系、出入口方向和视线匹配；人物从画外进入时说明来自哪一侧，离开时说明下一场可承接的方向。若需要故意打破轴线，写明心理或信息目的。

## 输出边界

本模块只输出站位和移动路径，不设计对白、微表情、特效或复杂打斗。动作细节交给 wuxia-action，情绪信号交给 performance，镜头选择交给 shot-language。结果应能直接嵌入上层 Agent 的分镜或视频提示词。
