# 灯虹微表情与情绪表演库

## 输入

接收人物目标、当前情绪、隐藏情绪、触发事件、情绪强度和镜头时长。

## 执行

1. 调用 read 读取 skill://denghong-performance/references/performance-guide.md。
2. 区分人物表面表现与真实感受。
3. 选择眼神、眉眼、嘴角、下颌、呼吸、手部和身体姿态中的两到四个可见信号。
4. 按触发、压抑、泄露和恢复设计时间顺序。
5. 保持表演强度适合景别，特写使用更细微的变化。
6. 避免同时堆叠大量表情词和互相冲突的动作。

## 输出

输出表层情绪、隐藏情绪、触发点、可见信号、节奏和一段可嵌入视频提示词的表演描述。


## 完整执行检查表

### 任务确认

- 读取用户原始请求并判断本技能是否适用。
- 识别主要目标、输出类型和使用场景。
- 区分已确认信息、参考信息和待推断信息。
- 不把示例误当成硬性要求。
- 不扩大用户没有提出的范围。
- 记录用户指定的风格、画幅和限制。
- 记录是否有图片、视频、脚本或资产输入。
- 缺少关键选择时再调用 ask_user。
- 选项必须互斥且会改变后续流程。
- 没有必要时不打断用户。

### 资料与资产

- 只读取当前模式需要的 reference。
- 先读取总指南，再读取质量检查。
- 需要案例时才读取 casebook。
- 通过 skill:// 路径读取资料。
- 有资产标识时优先使用标识。
- 没有标识时才调用 asset_search。
- 多个候选资产不能默选错误对象。
- 记录资产的角色、场景或道具用途。
- 记录可确认的视觉锚点。
- 记录不可确认的区域。
- 不凭空添加品牌、文字和身份。
- 不把推断内容写成已验证事实。

### 方案编排

- 先写目标，再写执行动作。
- 把复杂任务拆成可检查阶段。
- 每个阶段写清输入和输出。
- 每个阶段写清失败条件。
- 保持主体、空间和时间连续。
- 只让明确要求的变量变化。
- 将固定项和允许变化项分开。
- 不用泛泛的“保持一致”替代具体锚点。
- 对主要结果给出可验证标准。
- 高风险步骤设置一次重试上限。
- 不用重复生成掩盖理解错误。

### 工具调用

- 只使用允许的原生工具。
- 调用 read 前确认资源确实相关。
- 调用 image_generate 前准备完整 prompt。
- 调用 video_generate 前准备明确起始状态。
- 传入正确的图片资产标识。
- 使用用户要求的画幅和时长。
- 记录工具返回状态。
- 记录新生成的资产标识。
- 记录访问地址或可用结果。
- 工具失败时保留失败阶段信息。
- 不把计划或草稿当成生成结果。
- 不在一次调用中混入未经确认的多个方案。

### 质量与交付

- 检查输出类型是否正确。
- 检查主体数量、身份和关键结构。
- 检查空间、道具和材质连续性。
- 检查动作、视线和方向连续性。
- 检查画面是否裁切或畸变。
- 检查是否出现额外人物。
- 检查是否出现文字、水印或界面。
- 检查是否出现随机品牌或无关道具。
- 区分结构错误和轻微审美差异。
- 结构错误只重试一次。
- 第二次仍有轻微差异时如实说明。
- 交付摘要必须对应真实结果。
- 交付中列出资产标识和已知限制。
- 未成功返回时不声称完成。

### 调用前复核

- 表层情绪是否明确。
- 隐藏情绪是否明确。
- 触发事件是否明确。
- 景别是否适合信号强度。
- 选择的信号是否不超过四个。
- 眼神焦点是否明确。
- 呼吸节奏是否可见。
- 手部动作是否可执行。
- 身体重心是否连贯。
- 是否包含压抑或泄露过程。
- 是否避免互相冲突的表情。
- 是否保持上一镜头状态。
- 是否不擅自添加对白。
- 是否不替用户编写剧情。
- 是否输出可嵌入描述。
- 是否标记强度风险。
- 是否说明远景限制。
- 是否说明特写细节。
- 是否把动作交给动作模块。
- 是否给出明确交付字段。

## 情绪拆分

先写人物想让别人看到的表层情绪，再写被压住或不愿承认的隐藏情绪。确定触发事件、情绪强度、镜头景别和可用时长。特写可以使用眼神、眉间、嘴角、下颌和呼吸的细微变化；远景应优先使用姿态、停顿和动作节奏。

## 可见信号

每次选择两到四个信号，按触发、压抑、泄露、恢复排列。眼神写焦点与偏移，呼吸写节奏与停顿，手部写握紧、放松或迟疑，身体写重心、肩背和动作幅度。不要同时堆叠互相矛盾的哭笑、怒惧和快速动作。

## 连续性

表演强度必须从上一镜头的状态发展而来，不能无原因跳到最高强度。隐藏情绪可以通过短暂泄露体现，但不替角色补写对白或剧情。动作与镜头景别不匹配时，先降低动作幅度或改用更近景别。

## 输出边界

只输出表演节奏和可嵌入 prompt 的描述，不直接生成媒体。站位交给 blocking，打斗身体动作交给 wuxia-action，镜头景别交给 shot-language。若用户只要求外部动作而不需要情绪，应明确减少表演模块。
