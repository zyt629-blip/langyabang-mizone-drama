# 灯虹视觉特效知识库

## 调用边界

负责特效外观和时序，不负责角色动作本身。特效必须依附动作、道具、环境或明确事件。

## 执行

1. 调用 read 读取 skill://denghong-vfx-language/references/vfx-guide.md。
2. 确定特效来源、触发点、形态、颜色、尺度和作用对象。
3. 设计生成、发展、峰值、衰减和残留五个阶段。
4. 明确粒子轨迹、速度、密度、光照反馈和环境交互。
5. 控制特效遮挡，保证人物动作和关键结构清晰。
6. 让特效强度与剧情等级和能量来源一致。

## 输出

输出特效来源、五阶段时序、视觉形态、运动规律、光照影响、环境反馈、遮挡限制和提示词片段。


## 完整执行检查表

### 任务确认

- 读取用户原始请求并判断本技能是否适用。
- 识别主要目标、输出类型和使用场景。
- 区分已确认信息、参考信息和待推断信息。
- 不把示例误当成硬性要求。
- 不扩大用户没有提出的范围。
- 记录用户指定的风格、画幅和限制。
- 记录是否有图片、视频、脚本或资产输入。
- 缺少关键选择时再调用 ask_user。
- 选项必须互斥且会改变后续流程。
- 没有必要时不打断用户。

### 资料与资产

- 只读取当前模式需要的 reference。
- 先读取总指南，再读取质量检查。
- 需要案例时才读取 casebook。
- 通过 skill:// 路径读取资料。
- 有资产标识时优先使用标识。
- 没有标识时才调用 asset_search。
- 多个候选资产不能默选错误对象。
- 记录资产的角色、场景或道具用途。
- 记录可确认的视觉锚点。
- 记录不可确认的区域。
- 不凭空添加品牌、文字和身份。
- 不把推断内容写成已验证事实。

### 方案编排

- 先写目标，再写执行动作。
- 把复杂任务拆成可检查阶段。
- 每个阶段写清输入和输出。
- 每个阶段写清失败条件。
- 保持主体、空间和时间连续。
- 只让明确要求的变量变化。
- 将固定项和允许变化项分开。
- 不用泛泛的“保持一致”替代具体锚点。
- 对主要结果给出可验证标准。
- 高风险步骤设置一次重试上限。
- 不用重复生成掩盖理解错误。

### 工具调用

- 只使用允许的原生工具。
- 调用 read 前确认资源确实相关。
- 调用 image_generate 前准备完整 prompt。
- 调用 video_generate 前准备明确起始状态。
- 传入正确的图片资产标识。
- 使用用户要求的画幅和时长。
- 记录工具返回状态。
- 记录新生成的资产标识。
- 记录访问地址或可用结果。
- 工具失败时保留失败阶段信息。
- 不把计划或草稿当成生成结果。
- 不在一次调用中混入未经确认的多个方案。

### 质量与交付

- 检查输出类型是否正确。
- 检查主体数量、身份和关键结构。
- 检查空间、道具和材质连续性。
- 检查动作、视线和方向连续性。
- 检查画面是否裁切或畸变。
- 检查是否出现额外人物。
- 检查是否出现文字、水印或界面。
- 检查是否出现随机品牌或无关道具。
- 区分结构错误和轻微审美差异。
- 结构错误只重试一次。
- 第二次仍有轻微差异时如实说明。
- 交付摘要必须对应真实结果。
- 交付中列出资产标识和已知限制。
- 未成功返回时不声称完成。

### 调用前复核

- 特效来源是否明确。
- 触发事件是否明确。
- 作用对象是否明确。
- 生成阶段是否清楚。
- 发展轨迹是否清楚。
- 峰值尺度是否合理。
- 衰减方向是否合理。
- 残留状态是否需要。
- 粒子是否服从重力和风向。
- 光照反馈是否符合主光。
- 是否遮挡关键动作。
- 是否遮挡人物身份。
- 是否改变空间结构。
- 是否改变天气和时间。
- 是否与连续镜头一致。
- 是否把动作交给动作模块。
- 是否把运镜交给运镜模块。
- 是否输出可嵌入 prompt。
- 是否标记过度特效风险。
- 是否给出明确交付字段。

## 触发与来源

先明确特效来自人物能力、兵器、设备、环境、碰撞还是天气，并写出触发事件和作用对象。没有来源和触发点的“炫酷特效”不应添加。颜色、形态和能量等级应服从题材、材质和光源，不能遮挡角色身份或动作接触点。

## 五阶段设计

生成阶段说明出现方式和起始位置；发展阶段说明轨迹、速度、密度和扩散；峰值阶段说明最大尺度、亮度和环境反馈；衰减阶段说明消散方向和残留；残留阶段说明余光、烟尘、碎屑或地面痕迹。每阶段都要与主体动作或环境反应对应。

## 物理与连续性

粒子、烟雾、火花、能量和冲击波要有重力、风向、碰撞和遮挡逻辑。连续镜头中保留颜色、来源、方向和残留状态；改变特效等级时说明剧情原因。不要让特效凭空改变时间、天气、建筑或人物服装。

## 输出边界

本模块只处理视觉特效，不设计人物动作、镜头路径或完整故事。身体动作交给 wuxia-action，动态镜头交给 camera-motion，场面关系交给 blocking。输出应是一段可嵌入视频 prompt 的特效描述及风险提示。
