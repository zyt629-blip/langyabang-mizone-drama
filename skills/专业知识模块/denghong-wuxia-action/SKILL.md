# 灯虹武侠仙侠动作库

## 调用边界

负责身体动作、兵器关系、施法手势和受击反馈。光效、粒子和能量外观交给视觉特效知识库。

## 执行

1. 调用 read 读取 skill://denghong-wuxia-action/references/action-guide.md。
2. 根据角色能力、武器、空间和情绪确定动作风格。
3. 将动作拆为预备、发力、接触、反馈和收势。
4. 明确重心、步法、手部、兵器轨迹和对手反应。
5. 受击表现需要对应打击方向、力度、身体部位和地面关系。
6. 施法需要明确手势起点、轨迹、完成姿态和身体代价。

## 输出

输出动作目标、五阶段动作链、空间路径、兵器或手势细节、受击反馈、连续性限制和提示词片段。


## 完整执行检查表

### 任务确认

- 读取用户原始请求并判断本技能是否适用。
- 识别主要目标、输出类型和使用场景。
- 区分已确认信息、参考信息和待推断信息。
- 不把示例误当成硬性要求。
- 不扩大用户没有提出的范围。
- 记录用户指定的风格、画幅和限制。
- 记录是否有图片、视频、脚本或资产输入。
- 缺少关键选择时再调用 ask_user。
- 选项必须互斥且会改变后续流程。
- 没有必要时不打断用户。

### 资料与资产

- 只读取当前模式需要的 reference。
- 先读取总指南，再读取质量检查。
- 需要案例时才读取 casebook。
- 通过 skill:// 路径读取资料。
- 有资产标识时优先使用标识。
- 没有标识时才调用 asset_search。
- 多个候选资产不能默选错误对象。
- 记录资产的角色、场景或道具用途。
- 记录可确认的视觉锚点。
- 记录不可确认的区域。
- 不凭空添加品牌、文字和身份。
- 不把推断内容写成已验证事实。

### 方案编排

- 先写目标，再写执行动作。
- 把复杂任务拆成可检查阶段。
- 每个阶段写清输入和输出。
- 每个阶段写清失败条件。
- 保持主体、空间和时间连续。
- 只让明确要求的变量变化。
- 将固定项和允许变化项分开。
- 不用泛泛的“保持一致”替代具体锚点。
- 对主要结果给出可验证标准。
- 高风险步骤设置一次重试上限。
- 不用重复生成掩盖理解错误。

### 工具调用

- 只使用允许的原生工具。
- 调用 read 前确认资源确实相关。
- 调用 image_generate 前准备完整 prompt。
- 调用 video_generate 前准备明确起始状态。
- 传入正确的图片资产标识。
- 使用用户要求的画幅和时长。
- 记录工具返回状态。
- 记录新生成的资产标识。
- 记录访问地址或可用结果。
- 工具失败时保留失败阶段信息。
- 不把计划或草稿当成生成结果。
- 不在一次调用中混入未经确认的多个方案。

### 质量与交付

- 检查输出类型是否正确。
- 检查主体数量、身份和关键结构。
- 检查空间、道具和材质连续性。
- 检查动作、视线和方向连续性。
- 检查画面是否裁切或畸变。
- 检查是否出现额外人物。
- 检查是否出现文字、水印或界面。
- 检查是否出现随机品牌或无关道具。
- 区分结构错误和轻微审美差异。
- 结构错误只重试一次。
- 第二次仍有轻微差异时如实说明。
- 交付摘要必须对应真实结果。
- 交付中列出资产标识和已知限制。
- 未成功返回时不声称完成。

### 调用前复核

- 人物能力是否明确。
- 武器或手势是否明确。
- 空间大小是否明确。
- 地面条件是否明确。
- 情绪和胜负目标是否明确。
- 预备动作是否可见。
- 发力路径是否明确。
- 接触点是否明确。
- 受击反馈是否符合方向。
- 收势是否能承接下一动作。
- 重心是否真实。
- 步法是否连续。
- 兵器长度和握持是否稳定。
- 施法轨迹是否完整。
- 是否避免肢体扭曲。
- 是否避免瞬移和穿模。
- 是否把特效交给特效模块。
- 是否把镜头交给运镜模块。
- 是否输出动作 prompt 片段。
- 是否给出明确交付字段。

## 动作选择

根据人物能力、武器重量、空间大小、地面条件、情绪和胜负目标选择动作风格。轻快、沉重、克制、失控和仙侠施法都要通过重心、步法、速度和恢复时间体现，不能只贴风格标签。动作必须能在给定时长内完成。

## 五阶段细化

预备写重心、脚步、视线和手部起点；发力写躯干、肩臂和武器轨迹；接触写打击点、阻挡或能量连接；反馈写受力方向、失衡、疼痛和环境反应；收势写结束姿态、呼吸和下一动作入口。每一步都明确空间方向。

## 兵器与施法

兵器要保持握持手、长度、刃口或受力面一致；交锋要说明谁主动、谁格挡、接触后如何分开。施法要说明手势起点、轨迹、完成姿态和身体代价。受击不能瞬移或无视地面、墙面和障碍物。

## 输出边界

只提供可执行身体动作和连续性限制，不负责粒子、光效、镜头或站位总表。特效交给 vfx-language，镜头交给 camera-motion，复杂场面交给 action-director。结果以动作链和 prompt 片段交付。
