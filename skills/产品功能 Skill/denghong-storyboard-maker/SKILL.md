# 灯虹故事板生成

## 类型判断

1. 用户提供明确故事、剧情梗概或连续事件时生成九格故事板。
2. 用户没有故事且提供人物图片时生成静态角色概念板。
3. 用户没有故事且提供产品或道具图片时生成静态资产概念板。
4. 图片同时含人物和产品时，调用 ask_user 让用户选择人物概念板或资产概念板。
5. 没有故事也没有图片时，调用 ask_user 让用户选择上传人物、上传资产或输入故事。

## 九格故事板流程

1. 调用 read 读取 skill://denghong-storyboard-maker/references/storyboard-guide.md。
2. 将故事压缩为九个有因果关系的关键节点。
3. 为每格确定景别、机位、动作、表情、环境和连续关系。
4. 有参考图时将图片资产标识传入 image_generate 的 image_asset_ids。
5. 设置 aspect_ratio 为 16:9，生成九格故事板。

## 无故事流程

1. 调用 read 读取 skill://denghong-storyboard-maker/references/concept-board-guide.md。
2. 只分析输入主体，不设计事件、冲突、动作发展或结局。
3. 人物图片生成角色主视觉、多角度、表情、服装材质和自然姿态。
4. 产品图片生成主视觉、多角度、结构、材质、部件和静态应用状态。
5. 调用 image_generate 并传入参考图资产标识。

## 检查

调用 read 读取 skill://denghong-storyboard-maker/references/quality-checks.md。检查画格数量、主体身份、结构、服装、场景和光线一致性。出现缺格、换脸、结构漂移或错误叙事时只重试一次。

## 交付

交付生成类型、最终图片资产、图片资产标识和检查结论。


## 完整执行检查表

### 任务确认

- 读取用户原始请求并判断本技能是否适用。
- 识别主要目标、输出类型和使用场景。
- 区分已确认信息、参考信息和待推断信息。
- 不把示例误当成硬性要求。
- 不扩大用户没有提出的范围。
- 记录用户指定的风格、画幅和限制。
- 记录是否有图片、视频、脚本或资产输入。
- 缺少关键选择时再调用 ask_user。
- 选项必须互斥且会改变后续流程。
- 没有必要时不打断用户。

### 资料与资产

- 只读取当前模式需要的 reference。
- 先读取总指南，再读取质量检查。
- 需要案例时才读取 casebook。
- 通过 skill:// 路径读取资料。
- 有资产标识时优先使用标识。
- 没有标识时才调用 asset_search。
- 多个候选资产不能默选错误对象。
- 记录资产的角色、场景或道具用途。
- 记录可确认的视觉锚点。
- 记录不可确认的区域。
- 不凭空添加品牌、文字和身份。
- 不把推断内容写成已验证事实。

### 方案编排

- 先写目标，再写执行动作。
- 把复杂任务拆成可检查阶段。
- 每个阶段写清输入和输出。
- 每个阶段写清失败条件。
- 保持主体、空间和时间连续。
- 只让明确要求的变量变化。
- 将固定项和允许变化项分开。
- 不用泛泛的“保持一致”替代具体锚点。
- 对主要结果给出可验证标准。
- 高风险步骤设置一次重试上限。
- 不用重复生成掩盖理解错误。

### 工具调用

- 只使用允许的原生工具。
- 调用 read 前确认资源确实相关。
- 调用 image_generate 前准备完整 prompt。
- 调用 video_generate 前准备明确起始状态。
- 传入正确的图片资产标识。
- 使用用户要求的画幅和时长。
- 记录工具返回状态。
- 记录新生成的资产标识。
- 记录访问地址或可用结果。
- 工具失败时保留失败阶段信息。
- 不把计划或草稿当成生成结果。
- 不在一次调用中混入未经确认的多个方案。

### 质量与交付

- 检查输出类型是否正确。
- 检查主体数量、身份和关键结构。
- 检查空间、道具和材质连续性。
- 检查动作、视线和方向连续性。
- 检查画面是否裁切或畸变。
- 检查是否出现额外人物。
- 检查是否出现文字、水印或界面。
- 检查是否出现随机品牌或无关道具。
- 区分结构错误和轻微审美差异。
- 结构错误只重试一次。
- 第二次仍有轻微差异时如实说明。
- 交付摘要必须对应真实结果。
- 交付中列出资产标识和已知限制。
- 未成功返回时不声称完成。

## 输入优先级与唯一依据

先读取用户当前选中的图片资产标识。若用户只指向素材库中的图片而未给标识，调用 asset_search；若检索到多个候选，调用 ask_user 让用户选择。图片是人物、产品或道具时，锁定可见的轮廓、颜色、材质、比例和身份特征。参考图不能确认的区域可以自然补全，但补全不能反过来改变已确认区域。

## 严格的故事分流

“故事”必须包含人物或主体、事件或目标，以及至少一个时间上的变化。只有一句名称、一个人物、一个产品、一个地点或一组形容词，不视为故事。此时不得擅自补写起因、冲突、高潮或结局，必须进入静态角色设定版或产品道具概念版。用户明确说“没有故事，只做设定图”时，禁止生成剧情镜头。

## 人物静态设定版

头像或半身照只用于锁定脸部、发型、肤色和年龄感。若服装不可见，根据衣领、发饰、妆容、色彩和题材补全一套简洁、自然、无品牌的服装；没有线索时不推断真实职业或身份。设定板包括主视觉、全身三视图、头像转面、表情、服装材质、鞋履配饰和自然动作参考。动作只是静态姿态，不构成故事事件。

## 产品静态概念版

产品或道具设定板包括主视觉、正侧背和俯视等多视图、核心结构、材质颜色、关键部件、尺寸或人体工学关系、三种使用状态以及材质特写。所有模块属于同一个资产。未展示结构按产品功能和制造逻辑补全，不增加品牌、文字或不相干道具。使用状态必须是无剧情的产品展示姿态。

## 九格叙事节点

用户提供故事后，将其压缩为九个有因果的节点：建立人物时间地点；目标或异常出现；主体开始行动；阻碍增强；信息或关系改变；冲突升级；关键选择；高潮动作或情绪爆发；结果、反转或悬念。每格只能承载一个主要事件，不能用重复站姿凑格数。若故事不足九个事件，使用环境、反应、道具特写和因果过渡补足，但不得改变用户结局。

## 镜头设计

九格至少覆盖全景、中景、近景和特写。每格记录序号、景别、机位高度、观察角度、主体位置、动作、表情、前中远景职责、光线、色彩和与上一格的连续关系。镜头变化必须服务叙事：建立地点用全景，信息变化用近景或道具特写，高潮用能读清动作的中近景，结果用稳定的全景或反应近景。避免连续多格同构图、同姿势和无意义换角度。

## 连续性锁定

九格必须共享人物身份、服装、发型、道具、场景结构、时间、天气和主光方向。允许随剧情变化的只有动作、表情、位置、破损和情绪。每次编译都列出跨格固定项，并为服装、道具和空间设置可追踪锚点。若用户指定角色参考图，将其资产标识传入 image_asset_ids；若只有纯文字，按故事描述建立最小必要视觉设定。

## Prompt 编译模板

Prompt 先声明输出类型和画幅，再写参考资产一致性锁定、统一美术风格、九格阅读方向和网格排版。随后逐格写剧情、景别、机位、动作、表情、环境、光线和连续关系。结尾写排除项：无额外人物、无错位道具、无多余文字、水印、UI、品牌、重复画格、肢体错误、换脸和场景漂移。静态设定版不写剧情节点，不使用“镜头一至九”的叙事语言。

## 生成与记录

调用 image_generate 时使用完整 prompt；有参考图就传入对应 image_asset_ids，纯文字故事不虚构资产标识。aspect_ratio 默认 16:9，asset_name 根据输出类型使用“九格剧情故事板”“人物角色设定版”或“产品道具概念版”。记录工具返回的状态、图片资产标识和访问地址；未成功返回时不得声称完成。

## 检查与重试

故事板检查九格数量、阅读顺序、因果关系、镜头覆盖、角色身份、道具连续性、空间连续性和文字清洁。静态设定板检查模块是否齐全、所有视图是否同一角色或资产、服装与材质是否统一。出现缺格、重复格、换脸、结构漂移、剧情顺序错乱或文字残留时，只针对错误项强化 prompt 并重试一次。第二次仍有轻微差异，保留较优结果并如实说明，不无限重试。

## 交付摘要

剧情输出九格摘要和每格一句新信息；人物输出脸部锁定与服装补全摘要；产品输出结构锁定与补全摘要。所有结果都附输出类型、参考资产标识、图片资产标识、连续性检查结论和已知限制。不得把静态设定版描述成已经发生的故事。
